## Entities

### Service

Represents a monitored system component. Referenced by `Alert` and `Incident`.

| Field | Type | Constraints |
|-------|------|-------------|
| `name` | `string` | Required; unique within the store; PK in future DB |

**Seed**: 5 services — `payment-api`, `auth-service`, `order-service`, `inventory-api`, `notification-worker`

---

### Alert

A detected problem on a service. Read-only after creation (status changes are out of scope for this feature).

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `string` | Required; unique (e.g., `alert-001`) |
| `service` | `string` | Required; references a Service name |
| `description` | `string` | Required; human-readable summary |
| `severity` | `"critical" \| "high" \| "medium" \| "low"` | Required |
| `status` | `"firing" \| "resolved"` | Required |

**Seed**: 6 alerts:
- `alert-001` — `payment-api`, `"High error rate on /checkout"`, `critical`, `firing`
- `alert-002` — `auth-service`, `"JWT validation failures spike"`, `high`, `firing`
- `alert-003` — `order-service`, `"DB connection pool exhausted"`, `critical`, `firing`
- `alert-004` — `inventory-api`, `"Cache hit rate below threshold"`, `medium`, `resolved`
- `alert-005` — `notification-worker`, `"Email delivery queue stalled"`, `high`, `resolved`
- `alert-006` — `payment-api`, `"Latency p99 > 2s"`, `medium`, `resolved`

**Validation rules**:
- `status` must be `"firing"` or `"resolved"` (zod enum)
- `severity` must be one of the four levels (zod enum)

### Incident

A formalized operational event opened by the agent. Can transition from open to resolved.

| Field | Type | Constraints |
|-------|------|-------------|
| `id` | `string` | Auto-generated (e.g., `inc-<timestamp>-<random>`); unique |
| `title` | `string` | Required; non-empty |
| `service` | `string` | Required; references a Service name |
| `severity` | `"critical" \| "high" \| "medium" \| "low"` | Required |
| `status` | `"open" \| "resolved"` | Default: `"open"` |
| `createdAt` | `number` | Unix timestamp (ms); set at creation |
| `resolvedAt` | `number \| null` | Unix timestamp (ms); set when resolved; `null` otherwise |

**State transitions**:
```
open ──► resolved
```
No other transitions in this scope.

**Validation rules**:
- `title` must be non-empty string (zod `.min(1)`)
- `severity` must be one of the four levels (zod enum)
- `resolveIncident(id)` throws `IncidentNotFoundError` if `id` is not present

---

### TraceEvent

An immutable record of one step in the agent's reasoning process. Produced by strategies; never modified after creation.

| Field | Type | Constraints |
|-------|------|-------------|
| `type` | `"thought" \| "action" \| "observation" \| "plan" \| "critique" \| "answer"` | Required |
| `content` | `string` | Required; human-readable text |
| `tool` | `string \| undefined` | Present only when `type === "action"` |
| `toolArgs` | `Record<string, unknown> \| undefined` | Present only when `type === "action"` |

**Event semantics**:
- `thought` — the model's internal reasoning text before a tool call (from `AIMessage.content` when `tool_calls` are present)
- `action` — a single tool invocation (from `AIMessage.tool_calls[n]`; carries `tool` name and `toolArgs`)
- `observation` — the result of a tool call (from `ToolMessage.content`)
- `plan` — the list of steps generated by the Plan-and-Execute planner (content is the formatted plan)
- `critique` — a revised plan produced by the replanner (content is the updated plan)
- `answer` — the final natural-language response (from the last `AIMessage` with no `tool_calls`)

**Expected sequence for ReAct**:
```
thought → action → observation → [thought → action → observation →]* answer
```

**Expected sequence for Plan-and-Execute**:
```
plan → [action → observation →]+ [critique →]* answer
```

### ExecutionMetrics

Measured performance data for a single strategy execution.

| Field | Type | Description |
|-------|------|-------------|
| `llmCalls` | `number` | Total LLM invocations during the execution |
| `latencyMs` | `number` | Wall-clock milliseconds from `.run()` call to result |

### ReasoningStrategy (interface)

The contract every strategy must fulfill.

```typescript
interface ReasoningStrategy {
  readonly name: string;
  run(input: string): Promise<{
    answer: string;
    trace: TraceEvent[];
    metrics: ExecutionMetrics;
  }>;
}
```

## Relationships

```
Service ──< Alert        (one service → many alerts)
Service ──< Incident     (one service → many incidents)
```

No foreign-key enforcement in the in-memory store — `service` is a plain string field.

---

## In-Memory Store Interface

```typescript
interface IStore {
  getAlerts(status?: "firing" | "resolved"): Alert[];
  createIncident(data: Pick<Incident, "title" | "service" | "severity">): Incident;
  resolveIncident(id: string): Incident;  // throws IncidentNotFoundError if not found
}
```

## Domain Errors

| Class | Extends | When thrown |
|-------|---------|-------------|
| `IncidentNotFoundError` | `Error` | `resolveIncident(id)` called with an unknown `id` |

```typescript
class IncidentNotFoundError extends Error {
  constructor(id: string) {
    super(`Incident not found: ${id}`);
    this.name = "IncidentNotFoundError";
  }
}
```
